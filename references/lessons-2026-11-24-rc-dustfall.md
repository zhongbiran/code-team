## 二、Token 与缓存

- Codex 侧缓存很好：Overmind 389K/452K = **86%**，Coder 944K/1042K = **91%**。
- MiniMax 侧**缓存其实命中很高**（2026-11-25 实测 cacheRead/total = **96.9%**）。
  ⚠ 此前"MiniMax 侧完全没有前缀缓存"的结论**已被实测证伪**。
  → 真正的成本是**缓存读取同样计费**，且每次调用重发整个累积上下文。
  → 杠杆是 **toolCalls × 平均上下文长度**（少轮次、少读文件、早停），不是"提高缓存命中率"。
- 三个 Codex 调用合计 input 2.31M / cached 2.05M（89% 命中），output 31K。
  Codex 侧不是瓶颈；**MiniMax 侧才是**。

## 三、工具调用量

P9 一个包 245 次调用，其中 build 16 次、redis 16 次、git 5 次。
P5 首跑 182 次调用，其中 grep 48 次 + read 53 次（全是"边写边找"）。

两个可修的点：
1. **run_code 里包 bash** → 统计上每次 bash 被记成两次工具调用，数字翻倍。
   真实动作数要用"bash 调用数"而不是"tool_calls 总数"。
2. **16 次 build 里大部分是被人家的中间态挡住** → 并行包各自编译 = 反复重编。
   → 需要**编译闸 + 共享层串行**，或一个包先编译到绿再放其它包写。
