# Worktree Safe Merge（并发隔离与安全合入）

## 1. 并行写代码必须隔离
- 凡是同时派发 ≥2 个写代码 Worker，每个 Worker 必须运行在独立的 `git worktree` 与独立分支（如 `wt/<planId>-<pkgId>`），且各包的 `Ownership` 文件白名单绝对无交集。
- 共享层公共文件（如根配置、全局路由注册表、公共类型入口）**单独成包，串行执行**，不与业务包并发。

## 2. 合入前四步硬核检查
在把任一 worktree 分支合回主开发分支前，必须依次执行：
1. `git fetch` 确认远端与目标分支最新基线，避免基于过期快照覆写他人提交。
2. 核对 `git diff --name-only <base>...HEAD`：确认改动文件 **100% 落在 brief 白名单内**；若出现越界改动，先剥离再合入。
3. **单侧文件保留原则**：处理分叉合入时，严禁整目录覆盖；仅一方新增的文件必须保留，冲突文件先检出基线版本再逐块合并。
4. **保留合并拓扑**：优先使用保留双亲关系的 `--no-ff` merge commit（或按仓库规范提交 PR），不随意 squash 破坏跨包溯源历史。

## 3. 清理纪律
- 合入成功并验证通过后，再执行 `git worktree remove` 与临时分支清理；未合入的 worktree 禁止直接删除。
