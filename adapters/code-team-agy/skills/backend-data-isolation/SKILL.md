# Backend & Data Isolation（后端工程与数据隔离红线）

**适用时机**：编写后端接口、数据库 Schema 迁移、缓存/队列逻辑或集成测试时激活。

## 1. 绝对红线：测试环境物理隔离（闸 4）
- 自动化测试**严禁连接生产数据库、预发共享库或现场 Redis**。
- 必须使用以下之一：内存数据库（SQLite `:memory:`）、临时独立测试库（带随机前缀并在 teardown 销毁）、本地 Docker 一次性测试容器、或接口层 Mock。
- 严禁在测试脚本或命令中硬编码生产连接串、密钥或真实生产域名（会被 `hooks.json` 的 `PreToolUse` 硬拦截）。

## 2. 接口与数据变更规范
1. **契约一致**：请求/响应结构与错误码严格对齐 `contract-first-architect` 落盘的契约文件，入口处必须做参数校验与边界防御。
2. **幂等与并发安全**：写接口（创建订单、状态流转、回调、消息消费）必须考虑重试幂等键与乐观锁/事务边界。
3. **迁移可回滚**：所有数据库 Schema 迁移采用“先扩后缩（Expand-and-Contract）”策略，禁止在单次变更中直接破坏性 `DROP COLUMN` 导致旧版本服务崩溃。
4. **结构化日志与错误语义**：区分 4xx 客户端错误与 5xx 服务端异常，严禁向前端泄露堆栈或内部 SQL/密钥细节。
